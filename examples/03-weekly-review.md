# 示例 03 · 一次周复盘(Bayesian Update)

OKR Doing Agent 不把复盘当成"自我审判",而是一次**用新证据更新判断**的过程。
这是 `2026-W27` 周复盘入口被填完后的样子。脱敏样例。

---

## 本周 3 Things

| # | 本周战果 | 对应项目 / KR | 结果 |
|---|---|---|---|
| 1 | 上线 OKR Doing Agent 公开仓库 | `[[Project/OKR做到系统]]` · KR1 | ✅ 做到 |
| 2 | 完成 3 篇方法论长文初稿 | `[[Project/内容增长]]` · KR2 | ⬜ 1/3 |
| 3 | 跑通 10 个真实用户安装 | `[[Project/OKR做到系统]]` · KR3 | ⬜ 没做到 |

## Bayesian Update

```text
Result   做到 1 / 部分 1 / 没做到 1
Reason   #2 低估了"把方法论写清楚"的时间;#3 安装链路里有一步在真实
         Codex 环境没复现,卡在 manifest 识别
Evidence 写作耗时是预估的 2.3 倍;安装失败集中在同一步 → 不是需求问题,
         是分发链路问题
Update   原判断"先冲安装量"→ 下调。新判断:本月主线是"把链路打磨到
         一次能装上"+"方法论内容",安装量是滞后指标,不强求
Action   下周第一步:录一条 60 秒安装 demo,自己在干净环境走一遍,
         把卡住的那一步写进 README 的 Troubleshooting
```

## 它在这里做的事

- 把"没做到"翻译成**证据**,而不是**缺点**。
- 用一周的真实数据,**更新了对下个月主线的判断**(从冲量 → 打磨链路)。
- 只产出**一个**下周第一步 —— 不是又开一张待办清单。

> 失败不进人格审判,进黑匣子数据。
